# Context Original Public API

This document records the practical public API surface of `pyrolyze.runtime.context`
and the `pyrolyze.runtime` re-export layer, based on actual repo usage rather than the
full implementation size of `context_original.py`.

The inventory is generated by:

```bash
PYTHONPATH=src uv run --python 3.12 python scripts/context_api_inventory.py
```

The script scans:

- `src/`
- `tests/`
- `examples/`

and separates hand-written consumers from generated/golden imports.

## Main Conclusion

The design target for a new `context_lcm.py` should be:

- the non-private export surface of `pyrolyze.runtime.context`
- the `pyrolyze.runtime` re-export layer
- the behavioral contracts exercised by tests

It should not be:

- every helper or internal mutation path inside `context_original.py`

## Lowering-Facing Runtime API

The inventory script captures lowering imports well, but it undercounts lowering
method calls because generated code usually operates on generic variables such as
`__pyr_ctx` and `__pyr_ctx_slot_1`, not on values constructed directly in source.

So this section is based on direct grep over generated and golden lowerings under:

- `tests/data/`
- `tests/actual_test_results/`

Observed lowering-facing runtime methods include:

- `pass_scope`
- `visit_slot_and_dirty`
- `slot_expr`
- `container_call`
- `component_call`
- `call_native`
- `event_handler_binding`

Observed lowering-facing helper exports include:

- `LiteralFunctionProvider`
- `SlotId`
- `dirtyof`
- `dm_from_dirty_state`
- `module_registry`
- `slot_params`
- `slot_params_dirt`

This is important because methods like:

- `RenderContext.slot_expr(...)`

are compiler-facing public API even if hand-written code rarely or never calls
them directly.

## Redesign Implications

The pure `@managed_context` rewrite should preserve:

1. Module-level export names used by hand-written code.
2. `RenderContext` methods and context-manager behaviors exercised by tests.
3. Lowering-facing runtime methods used by generated code:
   - `pass_scope`
   - `visit_slot_and_dirty`
   - `slot_expr`
   - `container_call`
   - `component_call`
   - `call_native`
   - `event_handler_binding`
4. Construction and identity semantics for:
   - `RenderContext`
   - `ModuleRegistry`
   - `SlotId`
   - `SlotIdPath`
   - `AppContextKey`
   - `DirtyStateContext`
5. Hook/state-effect helper types that external code imports directly.

The rewrite does not need to preserve:

1. Every helper inside `context_original.py`.
2. The original internal inheritance hierarchy if the external behavior is preserved.
3. Private mutation plumbing or original field layout.

## Recommended Next Step

Use this public API inventory as the front-door compatibility contract, then
design a new `context_lcm.py` around:

- explicit exported names
- explicit `RenderContext` behavior
- slot-context classes that are pure `@managed_context` implementations

and only keep internal compatibility shims where the inventory or tests show a
real external dependency.
