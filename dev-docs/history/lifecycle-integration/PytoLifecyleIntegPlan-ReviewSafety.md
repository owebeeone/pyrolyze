## 1. Findings

### [P2-1] The plan treats missing drain-first failure handling as an existing TM facility
**Location:** `pyrolyze/dev-docs/PytoLifecyleIntegPlan.md:186-189`, particularly the instruction to preserve the manager’s structured error and after-hook resilience behavior; resource hook integration at `:400-410` and cleanup acceptance at `:510-511`.

**Violated invariant:** One failing hook must not silently prevent mandatory retirement or cleanup for other participants. The controlling Phase F-1 reference explicitly requires drain-first dispatch and collected failures at `yidl-lifecycle/dev-docs/YidlTransactionalYidlPhaseF-1Plan.md:664-674` and `:735-769`. The pinned runtime does not supply that behavior: after-commit dispatch stops at the first exception at `yidl-lifecycle/src/yidl_lifecycle/transaction_yidl.py:138-142`; rollback and after-rollback dispatch are likewise fail-fast at `:85-103`. Manager teardown still clears the active transaction at `:232-234` or `:262-264`.

**Reproduction and impact:** Enlist A, B, and C under the publication key in that order. All prepare and apply successfully. A’s after-commit notification raises; B’s hook was to retire a replaced subscription, and C’s hook was to finalize another resource transition. Neither later hook runs, yet publication is committed and the transaction is discarded. An unchanged next render need not enlist B or C, so it cannot be assumed to repair their missed retirement. The existing single-participant after-hook test at `yidl-lifecycle/tests/test_lifecycle_decorator.py:865-885` proves retained publication, not resilient completion across participants.

**Required correction:** Distinguish the Phase F-1 intended contract from the pinned implementation in Existing TM Limits. Make completion/error handling for mandatory resource cleanup an explicit capability prerequisite before the affected hook migration removes legacy mechanisms. An approved lifecycle extension or an explicitly specified domain mechanism may satisfy it; merely “preserving” nonexistent manager behavior cannot. The user’s choice of notification/error policy remains gated.

**Closure/regression test:** Require a multi-participant characterization with the first after-commit hook raising and later mandatory retirement hooks observable. Cover after-rollback failure similarly. The approved solution must establish callback/cleanup cardinality, retained committed state, key/local-scope cleanup, error context, and subsequent-render recovery. Plan closure can be achieved by accurately recording the limitation and gating dependent work on this verification.

### [P2-2] I1 activates nested TM sharing before the local-scope prerequisite scheduled in I2
**Location:** `pyrolyze/dev-docs/PytoLifecyleIntegPlan.md:344-359` schedules live nested-context TM sharing; the necessary separation of local scope activity is deferred to `:361-375`.

**Violated invariant:** Each operational checkpoint must preserve local pass entry, scratch reset, and candidate finalization when transaction ownership changes. Sharing key activity cannot suppress these domain operations. The plan correctly states this invariant at `pyrolyze/dev-docs/PytoLifecyleIntegPlan.md:151-168`, but its slice ordering leaves the prerequisite outside I1.

**Reproduction and impact:** Apply I1’s construction changes while retaining the scope implementation assigned to I2. The parent opens `PASS_TX_KEY`; its nested render context now shares that TM. The nested authored callable enters `pass_scope()`, which selects `activate=False` because `is_scope_active()` checks shared key activity, not that context’s local activity (`pyrolyze/src/pyrolyze/runtime/context_state_lcm/context_base.py:255-263`). `_PassScopeHandle` consequently calls neither nested `begin_pass()` nor `end_pass()` (`pyrolyze/src/pyrolyze/runtime/context_state_lcm/_support.py:413-424`). Nested own-UI entries are not reset at `context_base.py:309-310`; subsequent direct native emissions append to them at `:733-740`. Thus two successful nested renders can retain both old and new UI instead of replacing the emission. Nested child visitation and resource finalization are also bypassed. Before I1, the nested context’s separate manager at `render_context.py:35-39` avoids this particular suppression.

**Required correction:** Make local-scope entry/reset/finalization a prerequisite in the same checkpoint that enables nested-TM sharing, or combine/repartition I1 and the necessary I2 work. A construction seam may land earlier only while live nested sharing remains disabled. Manager-identity verification alone is insufficient for the I1 exit.

**Closure/regression test:** At that checkpoint, use a nested authored component that emits native UI directly, rerender it with changed input, and verify exactly the new emission remains. Include nested child removal and a failing nested pass followed by recovery. Assert local scope entry/exit independently of manager identity and preserve transaction completion ownership according to the eventual I0 decision.

No finding is raised merely because those decisions remain open.

This matches stored `binding()` versus staged `owned()` behavior. I7 preserves the original fallback and warns that direct imports are not rerouted by environment selection (`:445-461`). The inspected selector and focused tests support that warning.
